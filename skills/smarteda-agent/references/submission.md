# Competition submission

Use only when the user requests submission. Verify the project ID, version, title and account against the intended project. Save the normal operating model and validate connector counts before submission.

The observed UI path is My designs → project context menu → Submit technical support (simulation competition). The October 2026 frontend uses POST /error/create with type, label, save_id, version, description, channel, agency, updateBy and updateByName. Resolve frontend exports and account fields from the current authorized session; hashes and IDs are not portable. Select the competition channel shown in the current UI.

Submit once and save the actual server response. HTTP/application status 200 with success text establishes creation, not judging acceptance. After an ambiguous failure, inspect submission history before retrying. Technical-support submission is separate from the competition website's netdisk materials link.

For recordings, verify native model contents and advancing simulation callbacks, then capture actual frames and preserve capture timestamps. A stale toolbar status is not a trustworthy engine state. Recover hidden canvas layout only after the correct model is loaded. Do not manufacture probe values or claim firmware execution from an analog recording.
