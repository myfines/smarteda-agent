# Security and private data

Use a dedicated authorized browser profile. Never commit profiles, credentials, cloud backups, exports or vendor runtime assets. Local backups and output can contain full designs and private URLs; keep them outside shared folders.

Cloud writes require an explicit target file and a backup. After an ambiguous write failure, inspect the saved state before retrying. The browser session has the permissions of its logged-in user; run only with trusted MCP clients.

For a suspected vulnerability, do not publish credentials, private designs or exploit payloads in an issue. Use the repository Security tab's private reporting option if available; otherwise open a minimal issue requesting a private contact channel without sensitive detail. No monitored response-time SLA is promised.
