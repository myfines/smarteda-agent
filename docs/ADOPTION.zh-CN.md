# SmartEDA Agent：试用到官方合作

这是社区维护的第三方适配器，不代表 SmartEDA 官方。目标是让没有视觉能力的 AI 通过结构化工具操作原生电路，并向平台提供可复现的集成接口需求。

## 15分钟评估流程

1. 克隆仓库，Node.js 20+，执行 `npm ci --ignore-scripts`、`npm test`。不需要账号即可验证 XML 与 MCP 协议。
2. 创建专用 Chrome 用户目录，配置 SMARTEDA_PROFILE。运行 `npm run doctor`；首次使用设 SMARTEDA_HEADLESS=false，在打开的浏览器自行登录。不要把密码交给工具。
3. 在自己的沙盒工程调用 smarteda_open，再调用 smarteda_read，确认工程、器件与连线数量。只打开、读取不改云端电路。
4. 导出原始工程，离线调用 smarteda_validate、smarteda_patch；审阅改动后，以当前 expectedFileId 调用 smarteda_apply。保存的备份应放在私有目录。
5. 调用 smarteda_simulate，核对真实仿真时钟；有已连接 Oscope 时调用 smarteda_scope_read。缓冲数据的采样新鲜度未确立，不能当作瞬时电压。
6. 用 smarteda_export 导出平台归档，重新打开核验，并恢复正常参数。记录工具版本、平台构建、原始与导出模型摘要；账号、工程ID、URL、波形与设计均保持私有。

自动化测试只能证明离线与协议行为。上述在线步骤需要实际执行后，才能记录该平台版本兼容。原生 MCU 执行与全链路混合仿真不在已验证范围。

## 给官方的可执行合作提案

建议先进行只读接口试点，提供自建沙盒工程演示与脱敏结果，再讨论写入权限。现阶段依赖内部 Qt/WASM 导出及动态前端模块，平台更新可能失效；适配器不应成为官方接口的替代承诺。

希望官方评估的最小接口：

| 能力 | 建议契约 | 验收 |
| --- | --- | --- |
| 工程读取 | 版本化模型、单位、稳定器件ID | 与原生导出一致 |
| 工程修改 | 版本前置条件、差异预览、事务回滚 | 拒绝覆盖过时版本 |
| 仿真控制 | start/stop/reset和明确状态 | 独立时间戳及运行ID |
| 数值读数 | 通道、单位、采样时间、运行ID | 可区分缓存与当前样本 |
| 归档导出 | 明确格式版本及校验和 | 保存后可重开 |
| 授权 | 最小权限、撤销、审计 | 不依赖复用用户会话令牌 |

合作方式可以是社区兼容性维护、官方沙盒试点或官方审核的集成。先争取技术评估，再讨论维护责任、商标使用、支持范围与授权。MIT仅覆盖本项目原创代码；不分发厂商运行文件。
